## Intent

**Problem:** Voice generation (`generate_voice.py`, Gemini TTS), word-timing alignment (`extract_word_timing.py`, Google STT/Chirp), and subtitle cue segmentation (`build_subtitle_cues.py`, deterministic DP) are three manually-run scripts with no producer-provenance field, so their pre-existing outputs would silently satisfy resume forever; and there is no proof the four chained stages (1.2-1.5) actually resume correctly together rather than only in isolation.

**Approach:** Add `voice_agent`, an orchestrator stage that runs the three existing tools in sequence -- no Claude/LLM judgment anywhere in this path (AD-1: none of the three legacy scripts call Gemini/Claude for reasoning; subtitle segmentation must never be re-judged by an LLM, AGENTS.md's existing policy) -- producing a schema-and-staleness-validated `SubtitleCuesContract`, reusing `run_bounded_agent_stage`'s exact retry/halt/resume shape. Prove full-chain resume (Stories 1.2-1.5) with an end-to-end test.

## Boundaries & Constraints

**Always:** `voice_agent` runs only once validated `FinalStoryPlanContract` and `VisualPlanContract` both exist. It has no Claude/Agent-SDK session -- its `call_agent` closure directly invokes the TTS, STT, and DP tools and wraps their combined result in a synthetic `ResultMessage` (`total_cost_usd` computed from real Gemini TTS + Google STT per-unit pricing, tracked via new `settings.py` constants) so it reuses `run_bounded_agent_stage` unchanged. Every result validates against `SubtitleCuesContract` -- schema shape, `produced_by`, and a staleness guard (its `source_narration_script` must equal the current `FinalStoryPlanContract.narration_script`) -- the segmentation's own quality gate is exclusively the tools' existing mechanical checks (STT's `MIN_EXACT_MATCH_RATIO=0.85`, DP's own recheck `MIN_ALIGNMENT_RATIO=0.98`, both already raising on failure), never re-judged by an LLM (AD-2). Ceiling 3 (AD-3: transient-failure-retry default, not the 4-ceiling generate-review-revise pattern -- no creative self-correction loop exists here). Ceiling exhaustion halts via the shared failure-report path (stage id `"voice_agent"`). A persisted valid, current-narration `SubtitleCuesContract` skips `voice_agent` entirely. `main()` chains `run_voice_stage` after the visual stage, exactly like every earlier stage -- no new dispatcher; each stage's own skip-check is what makes full-chain resume already work once wired.

**Never:** Implement Epic 2 (`veo_agent`/`stills_agent`). Modify `generate_voice.py`, `extract_word_timing.py`, or `build_subtitle_cues.py` in place. Re-tune the DP segmentation's generic tuning constants (word/duration bounds, pause thresholds, penalty functions) -- ported verbatim. Add any LLM call, reasoning step, or self-review to this stage.

**Renegotiated (post-review, 2026-09-17):** The legacy `PROTECTED_PHRASES`/`IMPACT_PHRASE`/`REFLECTION_PHRASE` constants and `validate_rendered_text`'s hard "an IMPACT cue containing exactly 'Don't try' must exist" check are literal text from one specific reel's narration, not generic tuning parameters -- porting them verbatim (as the original Never clause required) makes `build_subtitle_cues` fail every future reel whose narration doesn't contain that exact phrase, with no possibility of a retry ever succeeding. These must instead be derived per-run from the current `FinalStoryPlanContract`: the impact phrase from any scene's non-empty `impact_text` (skip the IMPACT-cue requirement entirely if no scene declares one), and the reflection phrase from `story_arc.viewer_reflection`. General protected-phrase-internal-boundary discouragement may be derived the same way (from scenes' `impact_text` values) or dropped if no such scenes exist -- word/duration bounds, pause thresholds, and penalty functions remain generic and still ported verbatim, unchanged.

|----------|--------------|---------------------------|----------------|

## Implementation Notes

- `voice_agent`'s `call_agent` closure ignores `feedback`/`previous_output` in practice (AD-3: there is no creative self-correction to feed back into a fixed TTS->STT->DP chain) but still accepts all three positional parameters `run_bounded_agent_stage` always passes, so the shared helper is reused byte-for-byte unchanged.
- Cost is computed in `orchestrator/run.py`'s `run_voice_pipeline`, not inside either tool: `count_words(narration_script) * GEMINI_TTS_INPUT_TOKEN_COST_USD` (input-text-token proxy; word count, not a real tokenizer, since none of the ported tools expose one) + `audio_duration_seconds * GEMINI_TTS_AUDIO_TOKENS_PER_SECOND * GEMINI_TTS_OUTPUT_TOKEN_COST_USD` + `audio_duration_seconds * STT_COST_PER_SECOND_USD`. The cost-rate constants (Tasks bullet 1) are plain module-level constants in `settings.py`, not new `Settings` dataclass fields -- they're pricing facts to reconfirm later, not per-run operator configuration like `PROJECT_ID`/`max_budget_usd`.
- `build_subtitle_cues`'s ported tool keeps the legacy script's full per-cue richness internally (`style_hint`, `duration_seconds`, `start_word_index`/`end_word_index`, `duration_warning`) since AGENTS.md forbids re-tuning any of that logic; `run_voice_pipeline` then maps only the five `Cue` fields the spec's Tasks bullet actually names into `SubtitleCuesContract`. This includes `PROTECTED_PHRASES`/`IMPACT_PHRASE`/`REFLECTION_PHRASE` and `validate_rendered_text`'s hard "Don't try" check, ported verbatim per the Never-section constraint even though they're specific to this one reel's narration -- a materially different future narration would fail this gate and halt after 3 attempts, which is the existing legacy behavior's own limitation, not something this story is scoped to fix.
- Wiring `run_voice_stage` into `main()` after the visual stage surfaced the same class of test gap Story 1.4's own Implementation Notes flagged: `test_asset_analyst.py`, `test_story_agent.py`, `test_visual_agent.py`, and `test_preflight.py`'s `test_run_main_returns_zero_when_preflight_passes` each stub earlier/sibling stages to return 0 without stubbing the new stage that now runs after them. Fixed by adding a `run_voice_stage` no-op stub (mirroring each file's existing stage-stub pattern) to all four files. Full suite re-run afterward: 156 passed in under a second, confirming no real TTS/STT calls leaked into unrelated stage tests.
- The spec's third verification command (a real, unmocked `python -m orchestrator.run source_images` run, to confirm the legacy `metadata/subtitle_cues.json` is rejected and `voice_agent` runs for real) was not executed -- it is explicitly flagged in the spec itself as blocked pending a real validated `FinalStoryPlanContract`/`VisualPlanContract`, neither of which exists yet (verified: the repo's current `metadata/final_story_plan.json` and `metadata/visual_plan.json` are both legacy manifests with no `produced_by`). Verified statically instead that `SubtitleCuesContract.model_validate` rejects the real pre-existing `metadata/subtitle_cues.json` (24 cues, no `produced_by`).

## Design Notes

**No Claude call for this stage, by design.** TTS/STT/subtitle-DP involve zero judgment -- the same reasoning `epic-1-context.md` gives for `preflight`'s sole stated no-judgment exception applies here too. `run_bounded_agent_stage` is agnostic to what `call_agent` does internally, so `voice_agent` reuses it unchanged by wrapping the three tools' combined output in a synthetic `ResultMessage`, rather than inventing a new resume/retry mechanism or paying for an unnecessary Claude session.

**The quality bar already lives in the legacy tools, not a new validator.** Unlike `story_agent`/`visual_agent` (which invented fresh scored quality bars), `extract_word_timing.py` and `build_subtitle_cues.py` already raise on their own mechanical thresholds -- `SubtitleCuesContract`'s job is provenance and staleness, not re-deriving a quality gate.

**Full-chain resume is mostly free.** Each stage already independently skips via its own persisted-contract check; adding a 4th chained stage the same way is sufficient for AC2/AC3 -- no new dispatcher, no new resume-pointer tracking.
