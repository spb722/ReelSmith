## Intent

**Problem:** Voice generation (`generate_voice.py`, Gemini TTS), word-timing alignment (`extract_word_timing.py`, Google STT/Chirp), and subtitle cue segmentation (`build_subtitle_cues.py`, deterministic DP) are three manually-run scripts with no producer-provenance field, so their pre-existing outputs would silently satisfy resume forever; and there is no proof the four chained stages (1.2-1.5) actually resume correctly together rather than only in isolation.

**Approach:** Add `voice_agent`, an orchestrator stage that runs the three existing tools in sequence -- no Claude/LLM judgment anywhere in this path (AD-1: none of the three legacy scripts call Gemini/Claude for reasoning; subtitle segmentation must never be re-judged by an LLM, AGENTS.md's existing policy) -- producing a schema-and-staleness-validated `SubtitleCuesContract`, reusing `run_bounded_agent_stage`'s exact retry/halt/resume shape. Prove full-chain resume (Stories 1.2-1.5) with an end-to-end test.

## Boundaries & Constraints

**Always:** `voice_agent` runs only once validated `FinalStoryPlanContract` and `VisualPlanContract` both exist. It has no Claude/Agent-SDK session -- its `call_agent` closure directly invokes the TTS, STT, and DP tools and wraps their combined result in a synthetic `ResultMessage` (`total_cost_usd` computed from real Gemini TTS + Google STT per-unit pricing, tracked via new `settings.py` constants) so it reuses `run_bounded_agent_stage` unchanged. **Remaining budget is checked immediately before each paid call (TTS, then STT) inside the pipeline itself (AD-8), not only once per attempt** -- matching the epic-wide invariant that every paid tool call checks budget synchronously before executing. **If a later step in the pipeline fails after an earlier paid step already succeeded, the cost already incurred is still recorded** (AD-9: the pipeline returns a partial-cost, `is_error=True` result instead of letting the exception propagate past the point where cost gets accounted) -- unaccounted real spend must never happen. Every result validates against `SubtitleCuesContract` -- schema shape, `produced_by`, a staleness guard (its `source_narration_script` must equal the current `FinalStoryPlanContract.narration_script`), **`alignment_ratio >= MIN_ALIGNMENT_RATIO` (AD-10, defense in depth -- the tools already enforce this at generation time, but a persisted file's own claimed ratio must also be checked on every resume-skip, not just structurally trusted), and that the referenced `audio/narration.wav` still exists (AD-11: cues without their audio are not a valid skip target)** -- the segmentation's own *content* quality gate remains exclusively the tools' existing mechanical checks (STT's `MIN_EXACT_MATCH_RATIO=0.85`, DP's own recheck `MIN_ALIGNMENT_RATIO=0.98`, both already raising on failure), never re-judged by an LLM (AD-2). Ceiling 3 (AD-3: transient-failure-retry default, not the 4-ceiling generate-review-revise pattern -- no creative self-correction loop exists here) for *recoverable* failures (TTS/STT/DP raising due to alignment quality); **a scene's `impact_text` not appearing anywhere in the narration is non-recoverable (AD-12: no amount of audio regeneration can fix a text-authoring mismatch) and halts immediately on the first occurrence, without consuming the retry ceiling**. Ceiling exhaustion (or an AD-12 non-recoverable halt) halts via the shared failure-report path (stage id `"voice_agent"`). A persisted valid, current-narration, current-audio `SubtitleCuesContract` skips `voice_agent` entirely. `main()` chains `run_voice_stage` after the visual stage, exactly like every earlier stage -- no new dispatcher; each stage's own skip-check is what makes full-chain resume already work once wired.

**Never:** Implement Epic 2 (`veo_agent`/`stills_agent`). Modify `generate_voice.py`, `extract_word_timing.py`, or `build_subtitle_cues.py` in place. Re-tune the DP segmentation's generic tuning constants (word/duration bounds, pause thresholds, penalty functions) -- ported verbatim. Add any LLM call, reasoning step, or self-review to this stage. Add generic auth/billing-failure detection to short-circuit retries (AD-13, deferred -- see `deferred-work.md`; distinguishing "this class of error can never be fixed by retrying" in general is real scope beyond this patch round, and the existing ceiling of 3 already bounds the damage).

**Renegotiated (post-review, 2026-09-17):** The legacy `PROTECTED_PHRASES`/`IMPACT_PHRASE`/`REFLECTION_PHRASE` constants and `validate_rendered_text`'s hard "an IMPACT cue containing exactly 'Don't try' must exist" check are literal text from one specific reel's narration, not generic tuning parameters -- porting them verbatim (as the original Never clause required) makes `build_subtitle_cues` fail every future reel whose narration doesn't contain that exact phrase, with no possibility of a retry ever succeeding. These are instead derived per-run from the current `FinalStoryPlanContract`: the impact phrase from the *first* scene's non-empty `impact_text` (skip the IMPACT-cue requirement entirely if no scene declares one), and the reflection phrase from `story_arc.viewer_reflection`. General protected-phrase-internal-boundary discouragement derives the same way (from every scene's non-empty `impact_text`, not just the first) or is empty if no such scenes exist -- word/duration bounds, pause thresholds, and penalty functions remain generic and still ported verbatim, unchanged. Shipped in `orchestrator/tools/deterministic_tools.py`'s `derive_impact_phrase`/`derive_protected_phrases`.

**Renegotiated further (post-second-review, 2026-09-17):** Added AD-8 through AD-13 above (per-call budget checks, partial-cost accounting on mid-chain failure, `alignment_ratio`/audio-existence resume gates, non-recoverable-vs-recoverable failure distinction for the impact-phrase-not-found case). None of these change the fundamental TTS→STT→DP shape or the no-Claude-session design; they close budget-safety and resume-safety gaps a second review found in the first patch round.

**Acceptance Criteria:** (first four verbatim from `docs/epics.md`'s Story 1.5; the rest added post-review)
- Given validated `FinalStoryPlanContract` and `VisualPlanContract` exist, when `voice_agent` runs, then it produces narration audio via the existing Gemini TTS tool, word-timing via the existing Google STT/Chirp tool, and subtitle cues via the existing deterministic DP tool, and the segmentation output is validated only by its own mechanical alignment-ratio gate, never re-judged by an LLM.
- Given a run halts partway through the chain (e.g. after narration succeeds but before the visual plan completes), when re-invoked, then it does not re-run `asset_analyst`/`story_agent`; it resumes from `visual_agent`.
- Given the full chain (1.2-1.5) has already completed for a reel, when invoked again, then no pre-production stage re-runs.
- Given `voice_agent`'s stage fails validation and exhausts its retry ceiling, when the run halts, then the failure report uses the same shared minimal envelope as every other stage's halt.
- Given TTS succeeds and then STT fails, when the attempt is marked failed, then the manifest's `budget_spent_usd` already reflects the TTS cost.
- Given remaining budget cannot cover the STT call's estimated cost, when `run_voice_pipeline` reaches that point, then it halts before calling STT.
- Given a persisted `SubtitleCuesContract` whose `audio/narration.wav` no longer exists, when the orchestrator invokes, then it is treated as absent and `voice_agent` runs for real.
- Given a scene's `impact_text` is not found anywhere in the narration, when `build_subtitle_cues` raises, then the run halts immediately without consuming further retry attempts.

## Implementation Notes

- `voice_agent`'s `call_agent` closure ignores `feedback`/`previous_output` in practice (AD-3: there is no creative self-correction to feed back into a fixed TTS->STT->DP chain) but still accepts all three positional parameters `run_bounded_agent_stage` always passes, so the shared helper is reused byte-for-byte unchanged.
- Cost is computed in `orchestrator/run.py`'s `run_voice_pipeline`, not inside either tool: `tts_payload["prompt_word_count"] * GEMINI_TTS_INPUT_TOKEN_COST_USD` (the actual built-prompt word count Gemini receives, preamble included -- not just the bare `narration_script`, which would understate spend) + `audio_duration_seconds * GEMINI_TTS_AUDIO_TOKENS_PER_SECOND * GEMINI_TTS_OUTPUT_TOKEN_COST_USD` + `audio_duration_seconds * STT_COST_PER_SECOND_USD`. This is the one normative cost formula; nowhere else computes cost independently. The cost-rate constants (Tasks bullet 1) are plain module-level constants in `settings.py`, not new `Settings` dataclass fields -- they're pricing facts to reconfirm later, not per-run operator configuration like `PROJECT_ID`/`max_budget_usd`.
- `build_subtitle_cues`'s ported tool keeps the legacy script's full per-cue richness internally (`style_hint`, `duration_seconds`, `start_word_index`/`end_word_index`, `duration_warning`) since AGENTS.md forbids re-tuning any of that logic; `run_voice_pipeline` then maps only the five `Cue` fields the spec's Tasks bullet actually names into `SubtitleCuesContract`. **Superseded by the Renegotiated section above:** the impact/reflection/protected phrases are no longer hardcoded -- they are derived per-run from the current `FinalStoryPlanContract`, closing the one-reel-only limitation this note originally (incorrectly) accepted as permanent.
- Wiring `run_voice_stage` into `main()` after the visual stage surfaced the same class of test gap Story 1.4's own Implementation Notes flagged: `test_asset_analyst.py`, `test_story_agent.py`, `test_visual_agent.py`, and `test_preflight.py`'s `test_run_main_returns_zero_when_preflight_passes` each stub earlier/sibling stages to return 0 without stubbing the new stage that now runs after them. Fixed by adding a `run_voice_stage` no-op stub (mirroring each file's existing stage-stub pattern) to all four files. Full suite re-run afterward: 156 passed in under a second, confirming no real TTS/STT calls leaked into unrelated stage tests.
- The spec's third verification command (a real, unmocked `python -m orchestrator.run source_images` run, to confirm the legacy `metadata/subtitle_cues.json` is rejected and `voice_agent` runs for real) was not executed -- it is explicitly flagged in the spec itself as blocked pending a real validated `FinalStoryPlanContract`/`VisualPlanContract`, neither of which exists yet (verified: the repo's current `metadata/final_story_plan.json` and `metadata/visual_plan.json` are both legacy manifests with no `produced_by`). Verified statically instead that `SubtitleCuesContract.model_validate` rejects the real pre-existing `metadata/subtitle_cues.json` (24 cues, no `produced_by`).
- **AD-8/AD-12's shared halt mechanism, and its one known rough edge.** `run_bounded_agent_stage` is frozen/reused unchanged, and its *only* hook for "halt this attempt immediately instead of retrying" is `budget_failure or result.subtype == "error_max_budget_usd"` (an exception from `call_agent` always just continues the retry loop, consuming an attempt). `run_voice_pipeline` therefore reuses that exact subtype for both an actual budget shortfall (AD-8, where the halt reason is accurate) and AD-12's non-recoverable phrase-not-found case (where `run_bounded_agent_stage`'s hardcoded fallback halt reason, `"Claude reached its remaining budget limit"`, is misleading -- it wasn't a budget problem). The real cause is not lost, though: `run_voice_pipeline` puts the actual message in the `ResultMessage.errors`/`.result` fields, which `run_bounded_agent_stage` writes into that attempt's own JSON file (`voice_agent_attempt_N.json`) before evaluating the halt condition, and that file is included in the failure report's `partial_artifact_paths` -- so the AD-12 diagnosis is one file-open away, not lost, just not in the top-line reason string. Fixing the top-line wording would require changing `run_bounded_agent_stage` itself, which every other story in this epic also depends on unchanged.
- **AD-9's partial-cost accounting only covers TTS and STT, not a "failed STT attempt's own cost."** If the STT call's underlying Google API request itself succeeds but `extract_word_timing`'s own 0.85 gate then rejects it, `run_voice_pipeline` records `stt_cost = 0.0` for that attempt (cost is only added after the whole `extract_word_timing.handler` call returns without raising) -- the failing STT call's own real spend is not separately estimated. This matches the spec's literal AD-9 scope (TTS spend preserved when STT-or-DP fails afterward) and Acceptance Criteria (which specifically say "given TTS succeeds and then STT fails, ... budget_spent_usd already reflects the TTS cost" -- TTS only). Speculatively estimating a failed STT call's own cost was judged out of scope for this patch round; flagged here rather than silently assumed away.

## Design Notes

**No Claude call for this stage, by design.** TTS/STT/subtitle-DP involve zero judgment -- the same reasoning `epic-1-context.md` gives for `preflight`'s sole stated no-judgment exception applies here too. `run_bounded_agent_stage` is agnostic to what `call_agent` does internally, so `voice_agent` reuses it unchanged by wrapping the three tools' combined output in a synthetic `ResultMessage`, rather than inventing a new resume/retry mechanism or paying for an unnecessary Claude session.

**The quality bar already lives in the legacy tools, not a new validator.** Unlike `story_agent`/`visual_agent` (which invented fresh scored quality bars), `extract_word_timing.py` and `build_subtitle_cues.py` already raise on their own mechanical thresholds -- `SubtitleCuesContract`'s job is provenance and staleness, not re-deriving a quality gate.

**Full-chain resume is mostly free.** Each stage already independently skips via its own persisted-contract check; adding a 4th chained stage the same way is sufficient for AC2/AC3 -- no new dispatcher, no new resume-pointer tracking.

**No separate `orchestrator/agents/voice_agent.py` file exists, by design.** `epic-1-context.md`'s directory-layout line lists `voice_agent` alongside the other per-story `AgentDefinition`s, but since this stage has no Claude/Agent-SDK session at all (see above), there is nothing to define -- the pipeline lives entirely as `run_voice_pipeline`/`run_voice_stage` closures in `orchestrator/run.py`. `epic-1-context.md` is updated (Tasks) so a future story doesn't assume otherwise.

**First non-empty `impact_text` wins.** If multiple scenes declare a non-empty `impact_text`, `derive_impact_phrase` takes the first one (scene order == narration order); `derive_protected_phrases` still discourages internal breaks in *all* of them, not just the first. This mirrors how `story_agent`'s own narration-writing already treats the earliest emotionally-central beat as primary.
