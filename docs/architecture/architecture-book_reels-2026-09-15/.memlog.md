- (direction by user) Goal: automate the currently-manual, sequential 14-script pipeline orchestration using Claude Agent SDK. Must decide which stages become Claude-agent-driven, which stay plain Gemini/Google calls, which stay deterministic code with no LLM.
- (constraint) Inherited from AGENTS.md policy: locked artifacts (final_story_plan.json narration, subtitle_cues.json, 8-shot visual timing) must not be rewritten/retimed without explicit user direction; one engineering change at a time; no versioned/suffixed script copies; generation succeeded != asset approved (visual QA required).
- (constraint by user) The metadata/*.json files (analyzed_assets.json, final_story_plan.json, word_timing.json, subtitle_cues.json, visual_plan.json, etc.) are fragile shared contracts between stages -- e.g. if analyzed_assets.json changes shape, every downstream stage breaks. Schema stability across stage boundaries is a first-class concern for the orchestration design.
- (direction by user) True end-state: user provides 6-10 raw screenshots as input; the system runs the entire pipeline autonomously (scripting/directing/rendering) and produces the final video with no manual step-by-step execution/verification by the user.
- (decision by user) Boundary rule (user-stated): Gemini/Google APIs are used ONLY for capabilities Claude Agent SDK cannot do natively -- image generation/editing (Imagen/Gemini image-edit), TTS audio synthesis, Veo video generation, Google STT/Chirp word-alignment. Everything else (image/screenshot understanding, story writing, review, revision, visual planning, orchestration, QA decisions) is built directly as Claude Agent SDK agents, not routed through Gemini text models.
- (direction by user) Multi-agent architecture: multiple specialized Claude Agent SDK agents, each with its own skill set and reference context, rather than one monolithic orchestrator loop.
- (version) claude-agent-sdk (Python) current PyPI release 0.2.152, requires-python >=3.10 -- verified via PyPI JSON API 2026-09-15.
- (decision) Confirmed via Context7 docs (code.claude.com/docs/en/agent-sdk): SDK provides agents={} dict of AgentDefinition(description, prompt, tools, model) for specialized subagents; @tool decorator + create_sdk_mcp_server() for in-process Python function tools (no separate process needed); can_use_tool callback + PreToolUse hooks for approval gates; session_id/resume/fork_session/session_store for pipeline state persistence across pauses; max_turns/max_budget_usd/task_budget for runaway-cost guardrails.
- (decision by user) Full autonomy end-to-end: no manual per-stage checkpoints; human reviews only the finished rendered video. The AGENTS.md locked-artifact policy (never rewrite narration/cues/timing without explicit direction) governs protecting an ALREADY-APPROVED reel from a later re-run clobbering it -- it does not block an agent's own self-correction loop during a single autonomous run of a new reel.
- (decision by user) Contract enforcement: every stage boundary validates its output before the next agent/tool consumes it. On validation failure the producing agent must self-correct/retry (reiterate), not pass bad data downstream.
- (decision by user) Runaway-cost guardrail required: a configurable per-run budget ceiling (SDK max_budget_usd/task_budget), plus an iteration/retry limit on any validate-and-reiterate loop, so a stuck agent cannot loop or spend indefinitely.
- (decision by user) Terminal failure semantics: hard halt + failure report. When an agent exhausts its iteration/retry limit and still can't produce a valid result, the run stops where it is and writes a diagnostic report (what failed, what was tried, artifacts so far) for later review. No live notify-and-wait, no degrade-and-continue substitution.
- (assumption) Default retry/iteration ceiling carries forward existing code precedent: MAX_ITERATIONS=4 (story quality loop equivalent), MAX_API_RETRIES=3 (transient API call retries) -- user did not object when offered; flagged [ASSUMPTION] in the spine for correction.
- (decision by user) Tool integration: refactor existing script logic (ingest, subtitle segmentation, Gemini/Veo/STT calls, Remotion render trigger) into plain importable Python functions wrapped with @tool/create_sdk_mcp_server, running in-process -- not subprocess/CLI shell-outs. Existing 14 root scripts are migrated into orchestrator/tools/, not called as external processes.
